# monitoring

Logging stack used to read the logs of the applications in Grafana
(exercise 2.10). It follows the course material but **without Prometheus**
(metrics are not needed to read logs, and it saves memory):

| Release | Chart | What it does |
| ------- | ----- | ------------ |
| `loki` | `grafana/loki` | Stores the logs (single instance, local filesystem). |
| `k8smon` | `grafana/k8s-monitoring` | Runs Grafana Alloy, which reads the pod logs of every node and sends them to Loki. |
| `grafana` | `grafana/grafana` | The UI, with Loki already configured as the default datasource. |

Everything runs in the `monitoring` namespace. The values files are tuned for a
small local cluster:

- [loki-values.yaml](loki-values.yaml): `SingleBinary`, one replica, and the
  chunk/results caches and the canary disabled (their default memory requests are
  several GB).
- [k8smon-values.yaml](k8smon-values.yaml): collects pod logs only.
- [grafana-values.yaml](grafana-values.yaml): the Loki datasource. The tenant id is
  `1` in the three files; it has to match.

## Install

[Helm](https://helm.sh/) is needed. Install the releases **in this order**
(Alloy needs Loki, Grafana needs Loki):

```bash
helm repo add grafana https://grafana.github.io/helm-charts
helm repo update
kubectl apply -f ../namespaces/monitoring.yaml

helm upgrade --install loki grafana/loki --namespace monitoring --values loki-values.yaml
helm upgrade --install k8smon grafana/k8s-monitoring --namespace monitoring --values k8smon-values.yaml
helm upgrade --install grafana grafana/grafana --namespace monitoring --values grafana-values.yaml

helm list --namespace monitoring
kubectl get pods --namespace monitoring
```

Do not interrupt `helm install`: if it is cut off the release stays in
`pending-install` and further `helm upgrade` fails with "another operation is in
progress". Fix it with `helm uninstall <release> -n monitoring` and install again.

## Open Grafana

```bash
kubectl port-forward --namespace monitoring svc/grafana 3000:80
```

Open http://localhost:3000 and log in as `admin`. The password is generated by the
chart and is **not** in the repository; read it from the Secret (PowerShell):

```powershell
[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String((kubectl get secret grafana -n monitoring -o jsonpath="{.data.admin-password}")))
```

or on Linux/macOS: `kubectl get secret grafana -n monitoring -o jsonpath="{.data.admin-password}" | base64 -d`.

## Looking at the logs

Open **Explore**, pick the **Loki** datasource, switch to *Code* mode and run
[LogQL](https://grafana.com/docs/loki/latest/query/) queries. Useful labels are
`namespace`, `container` and `service_name`.

```
{namespace="project"}                                  # all the logs of the project
{namespace="project", container="todo-backend"}        # only the backend
{namespace="project"} |= "rejected todo"               # todos refused by the backend
{namespace="project"} |= "created todo"                # todos that were saved
```

### Trying the 140-character limit (exercise 2.10)

Send a todo of 141 characters straight to the backend (the form already stops it in
the browser, so use `curl` or Postman against the backend), then look for it in
Grafana:

```bash
# from a pod inside the cluster, for example one of the app pods
kubectl exec -n project deploy/todo-app-dep -- node -e "fetch('http://todo-backend-svc:2345/todos',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({todo:'z'.repeat(141)})}).then(r=>console.log(r.status))"
```

The answer is `400` and the query `{namespace="project"} |= "rejected todo"` shows
`rejected todo (141 characters, limit 140): "zzzz..."`.

## Remove it

```bash
helm uninstall grafana k8smon loki --namespace monitoring
kubectl delete namespace monitoring
```
